# Оформление Google-таблиц (Sheets API)

Выстрадано на вставке столбцов в рабочий журнал: заказчик
трижды возвращал на доработку (цветная каша в строке над шапкой → жирный/обычный шрифт
вперемешку → размер 10 вместо 9). Правки форматирования съедали по полчаса. Больше никогда.

## Стандарты оформления (по умолчанию везде)

- **Шрифт данных: размер 9, обычный (bold=false)**. НЕ 10! Жирный — только шапка.
- Шапка столбцов: bold, WRAP, по центру, вертикально MIDDLE, фон лаванда `{r:0.851,g:0.823,b:0.914}`.
- Границы данных: сплошные чёрные со всех сторон + внутренние (`updateBorders`, style SOLID).
- Выравнивание чисел: CENTER + MIDDLE.
- Форматы чисел: штуки `#,##0` · деньги `#,##0" ₽"` · проценты `0%` · **ROMI `+0%;-0%;0%`**.
  🔴 **ROMI ТОЛЬКО КЛАССИЧЕСКИЙ: `(маржа − затраты) ÷ затраты`, 0% = окуп в ноль, минус = убыток.**
  Заказчик поймал «неполную формулу» (маржа ÷ затраты, где 100% = ноль — это «возврат», не ROMI).
  Любой коэффициент в таблице (маржа 50% и т.п.) — сразу с источником в примечании шапки, а в ячейках
  примечание «что на что умножили» с цифрами строки.
- Нейтральная заливка расчётных/справочных столбцов: светло-серый `{r:0.953,g:0.953,b:0.953}`.
- Вердикт-подсветки: зелёный `{0.773,0.918,0.824}` · жёлтый `{0.984,0.910,0.773}` · красный `{0.984,0.780,0.773}`.
- **Сигнальная подсветка «обратить внимание»: СИНЯЯ гамма** — вне палитры тепловой карты,
  иначе сливается: голубой `{0.812,0.886,0.953}` = 1-я ступень; синий `{0.561,0.769,0.933}` + ЧЁРНЫЙ bold =
  2-я ступень (белый текст на синем заказчик забраковал — не читается). Красить ОДИН столбец-якорь,
  не полосу (полосу по 3 колонкам тоже забраковал). Условия ступеней можно комбинировать через OR
  (относительный сигнал ИЛИ абсолютные деньги).
- Ширина новых колонок ~118 px (updateDimensionProperties), у названий товаров 300+.
- **WRAP на всех текстовых данных** (особенно названия товаров) — заказчик вернул лист из-за
  необрезанных названий; перенос строк входит в форматирование по умолчанию.
- **Названия товаров — только ПОЛНЫЕ, с фасовкой** («Средство … 1 л», не «Средство …»):
  иначе дубли фасовок неразличимы («кто из них кто? какой литраж?»).

## 🔴 Пайплайн вставки столбца (ВЕСЬ, не частями — иначе три захода на доработку)

`insertDimension` наследует формат соседа КУСКАМИ (где-то жирный, где-то фон, где-то ничего).
После вставки обязателен полный проход ОДНИМ batchUpdate:

1. **Строка 1 (над шапкой)** — красится отдельно! Снять фон соседа
   (`spreadsheets.get includeGridData fields=...effectiveFormat.backgroundColor` на W1) и залить им новые ячейки.
2. **Шапка (строка 2)**: текст + bold/WRAP/CENTER/MIDDLE + лавандовый фон.
3. **Данные (строки 3..конец журнала)**: textFormat {size 9, bold false} + MIDDLE +
   numberFormat + фон (белый или нейтральный серый) + `updateBorders` все стороны + inner.
4. Ширина колонки.
5. Примечания (см. ниже).
6. Проверка: прочитать 2-3 заполненные строки И спросить себя «шрифт 9? границы всюду? строка 1 закрашена?».

## Ловушки (каждая стреляла)

- **Merged-ячейки кампаний**: запись в НИЖНЮЮ ячейку объединения уходит в никуда, ошибки нет.
  Перед записью в диапазон — проверить merges (`spreadsheets.get fields=sheets(merges)`).
  Пакетный блогер: затраты одной суммой в merged I, ROMI строк = `V/($I$верх/N товаров)`.
- **Вставка колонок сдвигает всё правее** — скрипты, которые ищут колонку по тексту шапки, выживают,
  буквенные ссылки в заметках/памяти устаревают. После вставки перечитать шапку.
- **Формулы**: USER_ENTERED, ру-локаль — разделитель `;`, проценты в формулах писать
  `*17,4%` а не `*0,174` (требование заказчика — «сразу видно, что процент»).
  EN-имена функций (IF, MAX, VLOOKUP=ВПР — работают оба варианта).
- **ВПР по SKU числом** работает, если ключевая колонка числовая; при #Н/Д пробовать текст.
- **Тексты с ведущим «+»** — только RAW (иначе #ERROR!).
- **`values.clear` НЕ снимает basicFilter**, но при изменении длины данных диапазон фильтра
  устаревает → в скриптах пересборки листа ставить `setBasicFilter` заново каждый раз.
- Сортировка чисел в фильтре подписана «А→Я / Я→А» — это по значению, не по алфавиту
  (не «чинить»).
- Условные форматы добавляются в index 0 → перед повтором удалить свои старые (иначе дубли).
- Колонки большого журнала искать НЕ по буквам, а по тексту шапки (свой хелпер вроде `cols.py`).

## Примечания к ячейкам

- **Длинное объяснение** (что считается, откуда тянется, как обновляется) — ОДИН раз
  в примечании ШАПКИ столбца.
- **В ячейках** — коротко «что на что умножили»: `Продажи × ≈15% (товар 900 г)`.
  Если процент в примечании округлён, а формула точная — приписать
  «Точный % — в листе расчёта, здесь округлён» (заказчик пересчитывал
  на калькуляторе и нашёл расхождение в 30 ₽).
- Примечания ставятся `updateCells fields="note"` (rows/values по размеру диапазона).

## Пересборка листов-справочников

Порядок: очистка A1:Z3000 →
values.update → merges заголовка/сносок → форматы → freeze → setBasicFilter → вердикт-заливки.
Внизу листа — «памятка» merged-строками (правила + источники + команда пересборки).
Лист пересобирается ЦЕЛИКОМ, руками его не правят.

## Запуск

stdout Python на Windows — в utf-8 (`sys.stdout = io.TextIOWrapper(...)`), ₽/× роняют cp1251.
Доступ — сервисный аккаунт Google (JSON-ключ хранить вне репозитория). Для .xlsx-файлов — скил `excel-oformlenie`.
